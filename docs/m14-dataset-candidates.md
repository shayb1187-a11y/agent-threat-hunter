# ATH dataset discovery and assessment (2026-09-10)

Scope: public, legally usable telemetry that can *challenge* ATH (false positives under real noise, missed detections, investigation quality). Every claim below was checked against the source page, a README, an API listing, or a downloaded sample unless marked **UNVERIFIED**. Nothing larger than ~64 MB was downloaded; all samples are under `scratchpad/worker/samples/` and are listed in section 5.

Legend for "adapter work": none / small (column mapping in an existing adapter) / medium (new adapter, same shape as an existing one) / large (new format parser + semantic mapping).

## 2. Detailed candidate notes

### 2.1 DEDALE - Dataset for Evaluating Detection of APT among Logs and Events (RECOMMENDED Windows source)

- URLs verified: https://dedale.inria.fr/ (index), https://dedale.inria.fr/download.html, https://dedale.inria.fr/attack_scenario.html, https://dedale.inria.fr/rescousse.html, Dataverse record https://entrepot.recherche.data.gouv.fr/dataset.xhtml?persistentId=doi:10.57745/Y5JLDG (file list pulled via `/api/datasets/:persistentId/?persistentId=doi:10.57745/Y5JLDG`). Note: the dedale.inria.fr TLS chain fails strict verification (fetched with `curl -k`); the Dataverse host verifies fine.
- Publisher: INRIA / IRISA PIRAT team (M. Lanvin, F. Majorczyk). Paper: ESORICS 2025 workshops, doi 10.1007/978-3-032-16092-8_1. Contact in README: frederic.majorczyk@irisa.fr.
- License: Dataverse `termsOfUse` = Creative Commons Attribution 4.0 (CC BY 4.0). Site text: "You may redistribute, republish, and mirror the DEDALE dataset in any form. However, any use or redistribution of the data must include a citation to the DEDALE dataset and a link to this page."
- Real vs synthetic: emulated on a real virtualised testbed (RESCOUSSE, derived from SOCBED): "about 40 virtual machines (clients and servers) with different operating systems (Windows and Linux)", Internet-connected for real browsing; Windows 10 internal clients in an AD domain (`breach.local`, hosts `CLIENT1.breach.local`, `CLIENT2.breach.local`, an admin client, `internalserver` Ubuntu 16.04). Benign activity from the AURA generator (email, web, file ops, SSH, VPN); AURA schedule + execution logs are shipped (`userbehaviour_logs.zip`, 22.2 MB) so benign ground truth exists too.
- Telemetry and formats (README verified): Windows hosts -> Winlogbeat 7.10.2 ECS 1.5.0 JSON, one file for all computers for all four weeks (`system_logs_winlogbeat.zip`, 27,123,250,952 B). Sysmon is configured (config lives in gitlab.inria.fr/mlanvin/rescousse, which is behind an anti-bot wall - UNVERIFIED which Sysmon event IDs and whether the Security channel 4624/4625/4688 is shipped). Linux -> Auditbeat (10.9 GB zip) + syslog (125 MB). Packetbeat 28.2 GB. Network: PCAP per zone per week (90-275 GB each - not needed), Zeek per zone (0.4-4.4 GB), CICFlowMeter, Suricata alerts (24.6 MB).
- Window: 4 weeks, "first two weeks contain only benign activity ... APT-like attack begins on the third week and lasts 8 days"; labelled events span 2025-01-06T10:01Z to 2025-01-13T11:00Z.
- Attack narrative (attack_scenario.html): phishing email with macro Office doc -> PowerShell `Invoke-WebRequest` from 172.19.1.1 -> meterpreter reverse shell to 172.19.2.1 -> custom malware `scvhost.exe` beaconing to C2 172.19.0.2 -> registry persistence -> lateral movement to the domain-admin client via PrintNightmare -> SSH with admin key to the internal server -> collection -> stealthy exfiltration. A week-by-week activity table exists on the page.
- Labels (downloaded `system_logs_labels.zip`, 2,669,407 B): `system_labels/clients_1_and_2/malicious_events_class_1.jsonl` (9,566 events: CLIENT2 7,828, CLIENT1 1,738) and `..._class_1_and_2.jsonl` (10,593), plus `internal_server/*.jsonl` (auditbeat). Label files are verbatim copies of the malicious events, so joining back to the full log is by `@timestamp` + `winlog.record_id`/`agent.id`. Channel/EID mix of labelled Windows events: Sysmon 11 (6,639), 7 (2,922), 2 (315), 10 (141), 18/17 (123/122), 5 (122), 1 (121), 22 (12); PowerShell 800/4103 (33 each), 4104, 600, 400, 403. No Sysmon 3 and no Security-channel events appear among the labels (UNVERIFIED whether they are collected at all - network ground truth is on Zeek `conn.log` instead).
- ATH schema mapping (from the sample): Sysmon 1 -> `process`: `process.command_line`, `process.executable`, `process.name`, `process.pid`, `process.parent.*`, `user.domain/name`, `host.name`, `hash.sha256`, `winlog.event_data.IntegrityLevel/OriginalFileName/Company`; `signer/signature_status` empty (Sysmon 1 has no signer). Sysmon 10 -> not an ATH table today (handle access to lsass; would extend ATH-004 beyond command lines = W6). Sysmon 3 -> `network` (`source.ip`, `destination.ip/port`, `network.transport`, `winlog.event_data.Initiated` -> direction) if present. Security 4624/4625 -> `logon` with numeric `winlog.event_data.LogonType` (ATH numeric codes match directly; no Defender string mapping needed) if present.
- Adapter work: **large** - a new "Winlogbeat/ECS NDJSON" adapter (ECS field paths differ from Defender columns; channel + event.code dispatch; numeric logon types). Reuses the existing NDJSON reading path. The same adapter would serve any Elastic Agent/Winlogbeat export, which is a common real-world source.
- Rules that can plausibly fire: ATH-001 (Office -> PowerShell macro), ATH-002/003 (encoded/downloading PowerShell to external host), ATH-008 (`Expand-Archive`/archive staging during collection), ATH-010 (discovery), ATH-007/005/006 (lateral movement via PrintNightmare + admin logons, if Security channel exists), ATH-004 only if the attacker dumped LSASS by command line (UNVERIFIED). Two weeks of clean data give a genuine FP baseline for W1/W2 and a documented 8-day chain for W5/W8 (contamination by benign PowerShell/AURA activity).
- Weaknesses testable: W1, W2, W3 (several steps are single-rule MEDIUM events), W4 (4 weeks of logons if Security channel present), W5, W8.
- Recommendation: **USE NOW**. Storage caveat: the Winlogbeat archive is a single 27.1 GB zip for all hosts/weeks; uncompressed size UNVERIFIED (expect 150-300 GB of JSON). Stream-filter on download to a per-host/per-week NDJSON subset.

### 2.2 Splunk Boss of the SOC v3 (RECOMMENDED hybrid source)

- URLs verified: https://github.com/splunk/botsv3 (README raw), https://www.splunk.com/en_us/blog/security/botsv3-dataset-released.html, write-up https://www.jamesgibbins.com/botsv3/ (community, lists the official 61 questions).
- Publisher: Splunk (Kovar, Herrald, Brodsky et al., 2018). License: CC0 1.0 ("dedicated all copyright and related and neighboring rights ... to the public domain worldwide"). Questions/answers: "email us at bots@splunk.com" per the Splunk blog; the full 200/300-series questions with answers are reproduced in several community write-ups.
- Data: 320.1 MB compressed, **Splunk pre-indexed buckets only** (`botsv3_data_set.tgz`, MD5 d7ccca99a01cff070dff3c139cdc10eb). Sourcetypes include `wineventlog`, `xmlwineventlog:microsoft-windows-sysmon/operational`, `aws:cloudtrail`, `aws:cloudwatch*`, `aws:cloudwatchlogs:vpcflow`, `o365:management:activity`, `osquery:results`, `linux_audit`, `stream:dns/http/tcp/udp`, `symantec:ep:*`, `code42`, plus ~100 more. Requires Splunk Enterprise 7.1.7 + 24 add-ons to search natively; Splunk Free/trial is enough to load pre-indexed data.
- Window/hosts: starts 2018-08-20 (write-up); "30 hosts, 107 sourcetypes, ~2M events" appear only in third-party notes - UNVERIFIED.
- Scenario (write-ups): Frothly brewery attacked by "Taedonggang"; AWS access-key compromise 09:16 -> Bud makes an S3 bucket public (question asks for the exact CloudTrail eventID) -> phishing 09:55 -> Linux RCE CVE-2017-9791 on `hoth`/`gacrux` -> privilege escalation 11:34 -> coin miner on `BSTOLL-L` -> exfiltration 15:15; Windows hosts such as `FYODOR-L`; O365/Azure AD sign-ins.
- ATH mapping: Sysmon XML (`process`, `network`), WinEventLog Security text (`logon`), CloudTrail (`logon` + `control`), osquery/O365 dropped. Value vocab: Sysmon `LogonType` absent; Security 4624 has numeric type; CloudTrail unchanged.
- Adapter work: **large**. Step 1: load buckets into a throwaway Splunk Free instance and run `splunk cmd exporttool <bucket> out.csv -csv` (yields `_raw` + `sourcetype` + `host` per event; no volume licence involved). Step 2: parse `_raw` per sourcetype: Sysmon XML (`<EventData><Data Name=...>`), classic WinEventLog key/value text, CloudTrail JSON. Reusable for BOTS v1/v2.
- Rules: AWS-001/002 candidates (public-bucket + key abuse; whether AttachUserPolicy/CreateAccessKey occur is UNVERIFIED), ATH-002/003/010 on Windows, ATH-005 on O365/Windows logons.
- Weaknesses: W5 (61 graded questions = the best ready-made investigation rubric found), W7 (only genuine endpoint+AWS+SaaS incident found), W8, some W2.
- Recommendation: **USE NOW as the hybrid/W5 source**, but after DEDALE because of the Splunk-extraction step.

### 2.10 flaws.cloud CloudTrail logs (RECOMMENDED AWS source)

- URLs verified: blog https://summitroute.com/blog/2020/10/09/public_dataset_of_cloudtrail_logs_from_flaws_cloud/; file https://summitroute.com/downloads/flaws_cloudtrail_logs.tar (HEAD: 251,688,960 B, `application/x-tar`, Last-Modified 2020-10-09). Kaggle mirror exists (https://www.kaggle.com/datasets/nobukim/aws-cloudtrails-dataset-from-flaws-cloud) - use the primary.
- Publisher: Scott Piper (Summit Route). License: **UNVERIFIED** - no license statement found; the post frames it as a research dataset. Recommend a one-line email to confirm before redistribution; internal evaluation use is low-risk.
- Content: 1,939,207 events, 2017-02-12..2020-10-07, 9,402 unique IPs, 8,811 user agents, 1,242 distinct APIs; "formatted into the usual CloudTrail format of {Records[...]}, and gzipped". Anonymised with `wernicke` (consistent replacement of IPs/account IDs/keys) plus manual `REDACTED`. Activity: S3 bucket enumeration brute force, role-assumption brute force, 500k+ EC2 RunInstances attempts, account recon, IAM-user backdoor attempts, root/console usage - i.e. thousands of independent attackers against one small account, with the owner's genuine maintenance in between. No per-event labels; narrative only.
- ATH mapping: existing CloudTrail adapter handles `Records`; `logon` from ConsoleLogin/AssumeRole; `control` only for AttachUserPolicy/PutUserPolicy/CreateAccessKey/StopLogging/DeleteTrail - the other ~1,237 APIs become "unmapped" (this is W6 made concrete). Adapter: **small** (tar extraction + `.json.gz` support; check that denied calls with `errorCode` are kept, since most backdoor attempts here fail).
- Rules: AWS-001 (attempted policy attach + CreateAccessKey chains), AWS-002 (if any StopLogging/DeleteTrail attempts - UNVERIFIED). Weaknesses: W2 (owner admin actions vs attacker), W6, W8 (thousands of unrelated actors -> case fragmentation), W1 (multi-year baseline for cloud prevalence).
- Recommendation: **USE NOW**.

### 2.12 Kubernetes CI e2e audit logs (RECOMMENDED K8s benign source)

- URLs verified: gcsweb listing https://gcsweb.k8s.io/gcs/kubernetes-ci-logs/logs/ci-kubernetes-e2e-gci-gce/ (build ids e.g. `2065053743543488512`), artifacts https://gcsweb.k8s.io/gcs/kubernetes-ci-logs/logs/ci-kubernetes-e2e-gci-gce/2065053743543488512/artifacts/bootstrap-e2e-master/ (`kube-apiserver-audit.log` 507,679,070 B; `kube-apiserver.log` 186 MB), direct object https://storage.googleapis.com/kubernetes-ci-logs/logs/ci-kubernetes-e2e-gci-gce/2065053743543488512/artifacts/bootstrap-e2e-master/kube-apiserver-audit.log (Range requests work; first 1.5 MB downloaded to `samples/k8s_ci/`).
- Publisher: Kubernetes project CI (Prow). License/terms: **UNVERIFIED** - public bucket, no license file; treat as "public artefacts of an Apache-2.0 project" and do not redistribute.
- Real vs synthetic: real kube-apiserver 1.37 on real GCE clusters; the *workload* is e2e conformance tests, not humans, so it is benign-but-busy rather than "normal SRE traffic".
- Format: NDJSON `audit.k8s.io/v1` Events; policy from `cluster/gce/gci/configure-helper.sh` (`create-master-audit-policy`): many `None` rules for noisy system users, `Request` for kubelet status updates, `Metadata` default, and `RequestResponse` for some groups. ### 2.14 Kubernetes: honest assessment and fallback

No public dataset was found that contains realistic Kubernetes audit logs with *both* normal admin activity *and* labelled attacks (RBAC abuse, secrets dumps, SA-token theft, exec). Best available plan:

2. This is synthetic but structurally identical to production audit logs, and the ground truth is exact.
